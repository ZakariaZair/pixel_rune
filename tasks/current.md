- Default Rune presets.

- User can see a default Rune preview in the app.
- At least 3 default Runes exist.
- Rune model is serializable JSON.
- Active Rune payload includes a version, selected timestamp, and Rune payload.
- Active Rune selection state works in the current app session.
- Active Rune selection persists locally across app restarts.
- TypeScript passes with `npm run typecheck`.
- Native widget proof-of-concept is configured through Expo prebuild/CNG.
- No Supabase sharing, RevenueCat paywall, or custom editor is added yet.

## Notes

- The iOS widget target is generated by `plugins/withPixelRuneWidget.js`; no
  `ios/` folder is committed yet.
- The app-to-widget writer bridge is still required. It must write the serialized
  payload to App Group `UserDefaults` key `activeRunePayload` and request a
  WidgetKit reload.
- Do not start Supabase sharing until local selection and widget architecture are clear.
- The first WidgetKit proof of concept should target the small iOS widget size.
- Active Rune persistence uses `expo-secure-store` for the selected built-in Rune ID. The later WidgetKit handoff still needs App Group shared storage for the serialized active Rune payload.

## Widget testing workflow

This project needs a generated iOS native project or EAS Build to validate the
WidgetKit target. Expo Go cannot run this widget.

1. Generate native iOS files locally:

   ```bash
   npx expo prebuild --platform ios
   ```

2. Open `ios/PixelRune.xcworkspace` in Xcode.
3. Confirm the generated targets include the app target and `PixelRuneWidget`.
4. In Apple Developer capabilities, confirm App Groups includes
   `group.com.pixelrune.app` for both targets.
5. Build and run the app on an iOS simulator or device.
6. Add the small `Pixel Rune` widget to the home screen.
7. Until the app writer bridge is implemented, expect the widget to render the
   fallback heart Rune from the native Swift code.
